# Hammerhall CLI

Клиент кузницы: забирает задачи, отправляет решения на проверку и показывает профиль.

## Что это

Курьер между вашей папкой и платформой. Читает файл, отправляет текст,
печатает вердикт. Больше ничего — ни компиляции, ни тестов, ни подсчёта
очков. Всё это происходит на сервере.

## Как пользоваться

Клиент лежит внутри кузницы: клонировали репозиторий — и он уже здесь.
Ставить ничего не надо.

```bash
./hammerhall login                    # войти по почте и паролю — один раз на машину
./hammerhall pull MovCode0002         # забрать задачу в свой проект
./hammerhall submit MovCode0002.java  # отправить решение
./hammerhall profile                  # профиль кузницы по осям
./hammerhall logout                   # удалить ключ с этой машины
./hammerhall version                  # версия клиента — первое, что спросит поддержка
```

Windows — то же самое через `hammerhall.bat`. Флаги понимаются в любом месте
строки: `pull --force MovCode0002` и `pull MovCode0002 --force` — одно и то же.
Везде работают `--help`, `--no-color` (или переменная `NO_COLOR`), `--verbose`
(запросы и ответы — в stderr).

`pull` кладёт файл в пакет, объявленный в самом тексте задачи, под именем,
которое задаче дала платформа (`pull movcode0002` положит `MovCode0002.java`).
Уже существующий файл **не затирается**; `--force` перезаписывает, но прежний
файл сначала откладывается рядом — `MovCode0002.java.bak`.

`submit` ищет файл по имени внутри `src/main/java` — полный путь помнить не
нужно. Отправляется только файл из этой кузницы и только в UTF-8.

`profile` вне кузницы показывает список кузниц, где вы что-то решали.

### Коды возврата

| код | что значит |
|---|---|
| 0 | готово; для `submit` — решение зачтено |
| 1 | решение не зачтено (это вердикт, а не ошибка клиента) |
| 2 | ошибка: неверный вызов, файл, отказ платформы |
| 3 | платформа недоступна или не ответила вовремя — повторите позже |

## Ключ доступа

`hammerhall login` спрашивает почту и пароль — те же, что на сайте
hammerhall.io, — и получает ключ сам. Пароль вводится скрытно (в настоящем
терминале; из IDE или конвейера клиент честно предупредит, что ввод виден)
и никуда не сохраняется.

Ключ хранится в **`~/.hammerhall/credentials`** — один вход на машину для всех
кузниц. Каталог создаётся с правами 700, файл — 600, сразу при создании.
До 0.2.0 ключ лежал в `.hammerhall/config` внутри кузницы; при первом запуске
0.2.0 он переезжает сам, а файл из кузницы удаляется.

Каждый вход выпускает **новый** ключ, а прежние продолжают работать: дома и на
работе можно войти отдельно. `logout` удаляет ключ с этой машины, но на
платформе он остаётся действующим; смена пароля отзывает **все** ключи разом.

Ключ, выпущенный в личном кабинете, тоже подойдёт: `./hammerhall login --token`
(ввод скрыт). Аргументом командной строки ключ не принимается — там он остался
бы в истории терминала и был бы виден в списке процессов.

### Адрес платформы

По умолчанию — `https://api.hammerhall.io`, и это нельзя поменять файлом в
кузнице: кузницы клонируют и форкают, и строка `api=` в чужом форке отправила
бы пароль постороннему. Свой стенд — только явно: переменная `HAMMERHALL_API`
или флаг `--api`, и клиент громко скажет «адрес переопределён». `http://` —
только для своей машины (`localhost`, `127.0.0.1`, `::1`). Перенаправлений
клиент не выполняет: API их не делает, а ключ не должен уехать за ними.

## Версия и совместимость

Версия — в манифесте jar (`Implementation-Version`); клиент называет её
командой `version` и в каждом запросе — заголовком
`User-Agent: hammerhall-cli/0.2.0 (java …; …)`. Если платформа пришлёт
`X-Hammerhall-Min-Client` новее вашей версии, клиент один раз скажет «обновите
кузницу»; ответ `426` — версия больше не принимается.

Протокол отправки готов к очереди: на `POST /submit` платформа отвечает либо
вердиктом (`200`), либо «принято» (`202 {"submissionId", "status"}`), и тогда
клиент опрашивает `GET /submit/{submissionId}` (`202` — ещё в очереди, `200` —
вердикт), до 10 минут. Короткий `Retry-After` (до 30 с) у `429` и `503` клиент
выжидает сам — не больше двух раз; длинный (квота: «следующие завтра») — нет,
печатает текст платформы.

## Обёртка — контракт

То, что человек запускает (`hammerhall`, `hammerhall.bat`), живёт **в кузнице**,
а не здесь: клон кузницы и есть установка. Поэтому контракт обёртки записан
здесь — его обязана выполнять каждая кузница (молды правят его чатами кузниц):

1. Версия клиента прибита в обёртке и меняется **после** выхода релиза
   (иначе — «Не удалось скачать клиент»). Где версия живёт: `pom.xml` клиента,
   обе обёртки.
2. Jar берётся из релиза GitHub `Hammerhall/hammerhall-cli`, тег `v<версия>`,
   файл `cli-<версия>.jar`, и кладётся в `.hammerhall/cli-<версия>.jar` кузницы
   (`.hammerhall/*.jar` — в `.gitignore` кузницы).
3. Целостность: рядом в релизе лежит `cli-<версия>.jar.sha256` (с 0.2.0) —
   одна строка в формате `sha256sum`: 64 шестнадцатеричных знака, два пробела,
   `cli-<версия>.jar`. Обёртка сверяет первые 64 знака до первого запуска
   и при несовпадении удаляет файл и останавливается.
4. `hammerhall update` перекачивает **свою** версию (лечит битый файл);
   новую версию приносит обновление кузницы.
5. Java 25 — та же, что для кузницы.
6. Ключ — не забота обёртки: с 0.2.0 он в `~/.hammerhall/credentials`, и строку
   `.hammerhall/config` в `.gitignore` кузницы можно оставить для старых клонов.

## Сборка

```bash
./mvnw verify
```

Получится `target/cli-<версия>.jar` — один файл без зависимостей. Сборка
останавливается на не той Java (нужна 25+) или не том Maven (3.9+) — так велит
`maven-enforcer-plugin`; и на покрытии ниже 90 % строк и 80 % ветвей.

⚠️ В текстовых отчётах surefire у классов с `@Nested` бывает `Tests run: 0` —
это косметика вложенных контейнеров; настоящие числа — в XML-отчётах.

Все слова клиента — в `src/main/resources/io/hammerhall/cli/messages.properties`;
`MsgTest` сверяет ключи файла с кодом в обе стороны. Английский — файл
`messages_en.properties` рядом.
